# SEO: перевірка й розгортання

Перевірено 12 листопада 2026 року за [Front-End Checklist](https://github.com/thedaviddias/Front-End-Checklist), насамперед розділами SEO, HTML, Images і Performance. Це аудит коду; результати Google Search Console та відповіді production-сервера потрібно перевірити після розгортання.

## Що виправлено

| Пункти чекліста | Результат |
| --- | --- |
| Індексований HTML, одна H1, змістовні посилання | Основні 7 маршрутів мають окремі HTML-файли з заголовком, описом, основним текстом і навігацією ще до запуску JavaScript. На сторінці розкладу виправлено H1. |
| Унікальні title та meta description | Для основних сторінок налаштовані окремі тексти; для новин вони формуються з назви та анотації під час збірки. |
| Canonical, дублікати URL | Основні адреси без `?lang=uk` є канонічними. Українську й англійську версії більше не заявлено як окремі статичні сторінки в sitemap. |
| Sitemap і robots.txt | Sitemap містить усі основні маршрути. Якщо CMS доступна під час збірки, до неї додаються опубліковані новини. `robots.txt` вказує на sitemap і не блокує публічні сторінки. |
| Структуровані дані | Додані WebSite, EducationalOrganization з реальною адресою та альтернативною назвою школи, а на внутрішніх сторінках BreadcrumbList. |
| Соціальні прев’ю | Open Graph і Twitter Card містять окремий заголовок, опис, URL і фото будівлі ліцею. Додано favicon. |
| Локальні запити | Назва ліцею, повна назва, село Новий Білоус, Чернігівський район і поширена назва «Новобілоуська школа» включені природно до змісту або структурованих даних. |

## Для production

1. Збирайте сайт, коли Strapi працює: `cd frontend && npm ci && npm run build`. Якщо Strapi не на `http://127.0.0.1:1337`, задайте `SEO_CMS_URL` як базовий URL CMS. Перевірте повідомлення `SEO: generated ... HTML pages`; без CMS новини не потраплять у статичні файли й sitemap.
2. Налаштуйте Caddy в блоці віддачі frontend так: `try_files {path} {path}/index.html /index.html`. Інакше внутрішні адреси отримають HTML головної сторінки. Залиште наявні окремі проксі для `/api`, `/uploads` та адмінки. Перевірте `caddy validate`, тоді перезавантажте Caddy.
3. Перевірте HTTP-відповіді `/`, `/about`, `/events`, `/schedule`, `/public-info`, `/distance-learning`, `/power`, `/favicon.svg`, `/novobilouskyi-lyceum.webp`, `/robots.txt`, `/sitemap.xml` та кілька `/events/<slug>`. Для внутрішніх адрес перевірте відповідність `title`, canonical, опису й `og:url`.
4. У Google Search Console надішліть `sitemap.xml` і запитайте повторне сканування головної та важливих внутрішніх сторінок. Перевірте звіти про індексацію, канонічні адреси й Core Web Vitals. Сніпет формує Google, тому опис у видачі може відрізнятися від `meta description`.

## Ще потребує окремої роботи

- Англійська версія зараз перемикається через `?lang=en` і JavaScript, а неперекладений контент може залишатися українським. Для окремої індексації англійською потрібні стабільні серверні URL, повні переклади та `hreflang`.
- Нові або змінені новини потрапляють до статичного HTML і sitemap лише після повторної збірки. Якщо публікація в CMS відбувається без деплою, потрібен автоматичний запуск збірки або серверна генерація сторінок.
- Невідомі адреси за поточним SPA fallback можуть повертати HTTP 200. Для повного усунення soft 404 потрібна окрема логіка 404 на сервері.
- Фактичні швидкість, доступність, зовнішні посилання, відповідь production і вигляд прев’ю соцмереж неможливо підтвердити лише кодовим аудитом.

Не застосовуються до цього сайту без відповідного контенту: Product/Review/FAQ/VideoObject schema, affiliate та інтернет-магазин правила, SearchAction для відсутнього глобального пошуку.
