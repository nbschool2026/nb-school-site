# Контент у Strapi

## Як редагувати

1. Запустіть CMS у режимі `npm.cmd run develop` і відкрийте <http://localhost:1337/admin>.
2. У Content Manager виберіть модель, створіть або змініть запис.
3. Збережіть та **опублікуйте** запис. У моделях увімкнено Draft & Publish; неопубліковані зміни публічний сайт не читає.
4. Перезавантажте відповідну сторінку React-сайту.

Перед публікацією замініть демонстраційні відомості на перевірені матеріали школи. Стартові події більше не зашиті в коді; уже створені записи з позначкою «ДЕМО» зберігаються в локальній CMS. Приклади розкладу, контактів та працівників ще є в інших частинах сайту.

## Моделі й використання

| Модель Strapi | REST-шлях | Основні поля | Де використовується |
| --- | --- | --- | --- |
| School Profile (один запис) | `/api/school-profile` | назва, заголовок і текст головної, місія, контакти, години, `heroImage`, `aboutImage` | головна сторінка, «Про нас» та контакти у підвалі; частина оформлення й текстів поки задана в React |
| Event | `/api/events` | назва, slug, анонс, текст, категорія, дата, обкладинка, кілька фото (`photos`), YouTube URL (`youtubeUrl`), featured | головна, список і окрема сторінка події |
| Public Document | `/api/public-documents` | назва, slug, опис, оригінальний `file`, необов’язкова PDF-копія `previewPdf`, порядок | перегляд і завантаження на сторінці публічної інформації |
| Вчителі та адміністрація (Staff Member) | `/api/staff-members` | ПІБ, посада або предмет, опис, `photo`, `homepagePhoto`, порядок | сторінка «Про нас»; перший за порядком запис також показано на головній |
| Schedule Lesson | `/api/schedule-lessons` | клас, день, час, предмет, учитель, кабінет, порядок | розклад на головній |
| History Item | `/api/history-items` | рік, назва, текст, іконка, порядок | сторінка «Про нас» |
| Value Card | `/api/value-cards` | назва, текст, іконка, порядок | сторінка «Про нас» |
| Gallery Item | `/api/gallery-items` | назва, фото, альтернативний текст, порядок | модель готова; публічний інтерфейс ще не підключений |

Стартові записи для деяких моделей задаються в `cms/src/index.ts`. Для кожної такої колекції вони додаються лише тоді, коли в ній немає записів. `Event` і `Gallery Item` стартовими даними не наповнюються. Публічні права читання потрібних моделей також налаштовуються там під час запуску.

У Strapi 5 для редагування опублікованого запису потрібна і його чернеткова версія. Старі стартові записи без чернеток можуть бути видимими через публічний API, але відсутніми в Content Manager. У такому разі з папки `cms` запустіть `node .\scripts\repair-missing-drafts.cjs`: скрипт створює лише відсутні чернетки з опублікованих версій, не знімаючи записи з публікації. Нові стартові записи вже створюються через Documents API разом із чернетками.

### Як додати вчителя

У **Content Manager → Вчителі та адміністрація** створіть запис: `ПІБ`, `Посада` (можна вказати предмет), `Опис`, `Фото` та `Порядок`. Збережіть і опублікуйте українську версію — картка з'явиться на `/about`. За потреби додайте й опублікуйте англійський переклад ПІБ, посади та опису; фото спільне для мов. Менше значення `Порядок` показує картку раніше. Перший запис у цьому списку також використовується на головній, тому залиште для нього найменший порядок; окреме `Фото для головної` необов'язкове.

## Що зберігається в Git

- **У Git:** моделі, код API, стартові демонстраційні записи, документація та оптимізовані WebP у `cms/seed-media/`.
- **Поза Git:** `cms/.env` із секретами та робоча `cms/.tmp/data.db` з локальним адміністратором.
- **Знімок у Git:** `backups/cms-content.db` містить демонстраційний контент без адміністраторів, сесій і токенів; відповідні файли — у `cms/public/uploads/`. Див. [інструкцію зі створення та відновлення знімка](database-backup.md).
- **Медіафайли:** Strapi використовує `cms/public/uploads/`. Перед комітом нових фото або документів перевіряйте права на використання. Для робочого сервера потрібне постійне сховище і його власні резервні копії.

Git-знімок не замінює регулярну резервну копію робочої CMS. Перед змінами схем або перенесенням проєкту збережіть окрему копію SQLite-бази та медіафайлів. Не публікуйте локальний `.env`.

## Публічні документи

У **Public Document** додайте назву, опис і оригінальний файл PDF, DOC або DOCX у поле `file`, збережіть та опублікуйте запис. Для PDF кнопка «Переглянути» використовує сам оригінал. Для DOC/DOCX CMS автоматично створює PDF-копію в `previewPdf` під час збереження запису; оригінал лишається доступним через «Завантажити оригінал». Поле `previewPdf` можна заповнити вручну для старих записів, але для нових це не потрібно. Якщо конвертація не вдається, CMS відхиляє збереження з повідомленням про помилку, щоб не публікувати документ без перегляду.

На комп’ютері з CMS має бути встановлений LibreOffice. У Windows використовується `C:\Program Files\LibreOffice\program\soffice.com`; для іншого шляху задайте `LIBREOFFICE_PATH` у `cms/.env`. На Linux команда `soffice` має бути доступна через `PATH`. Локальне сховище медіафайлів Strapi є необхідним для цієї реалізації.

Після зміни коду перезапустіть CMS. Створіть новий DOCX без заповнення `previewPdf` і перевірте, що після збереження PDF-копія з’явилась автоматично. На `/public-info` перевірте перегляд і завантаження PDF та DOCX окремо. Для DOC також перевірте справжній файл цього формату. Якщо CMS повертає порожній список або помилку, демонстраційні документи не підставляються.

## Як додати нове поле або модель

1. Описати потребу й критерій готовності в [дорожній карті](roadmap.md).
2. Змінити схему Strapi та за потреби сторінку React.
3. Перевірити запис в адмінці, публікацію й відповідь API.
4. Оновити цю таблицю, [архітектуру](architecture.md) та інструкції запуску, якщо вони змінилися.

Моделі локалізовані через Strapi i18n. Українські записи збережено, англійські переклади редактор створює та публікує окремо. Покрокова [інструкція з перекладів](multilingual.md) пояснює перемикач і запасний український текст.

## Перевірка головної та сторінки «Про нас»

1. У **School Profile** замініть `heroImage` (головна) і `aboutImage` («Про нас»), змініть адресу, телефон або email, збережіть і опублікуйте. Після оновлення сторінок мають змінитися фото й контакти; email та посилання на карту також використовуються в підвалі сайту.
2. У **Staff Member** змініть `photo` (сторінка «Про нас»), `homepagePhoto` (картка на головній) й опис (`bio`) першого за полем `order` працівника та опублікуйте. Перевірте його картку на `/` і всі картки на `/about`.
3. У **History Item** додайте опублікований запис з новим роком. На `/about` історія має показати його в порядку років.
4. Змініть дати двох опублікованих подій. На головній мають бути саме чотири найновіші за датою, незалежно від прапорця `featured`.

## Зображення

Стартові зображення перенесено в CMS: два фото будівлі в **School Profile**, портрет директорки для сторінки «Про нас» і головної та портрет заступниці з виховної роботи Луценко Наталії Олександрівни. При першому запуску Strapi `cms/src/seed-media.ts` заповнює лише порожні поля; зміни редактора не перезаписуються. Після зміни схеми чи стартових фото перезапустіть Strapi. Зміни полів публікуйте в Content Manager.

Для нового фото спершу підготуйте WebP у папці `cms`:

```powershell
node .\scripts\optimize-image.mjs "C:\шлях\до\фото.jpg" "C:\шлях\до\фото.webp" 1600 80
```

Потім завантажте результат у Media Library і виберіть його в потрібному полі. Число `1600` обмежує ширину, `80` задає якість; обидва параметри можна не вказувати. Для фото потрібен коректний альтернативний текст. Якщо контент треба відтворювати після клонування, оновіть [знімок бази](database-backup.md) і додайте створені файли з `cms/public/uploads/` у той самий коміт.
